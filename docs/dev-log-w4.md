# W4 开发日志：四个红灯翻绿三个，规则引擎有了第一版

> 状态：W4 收官。性能四指标三项达标一项降级收口；规则 DSL v1 + 解析器 + 匹配引擎落地，3 条示例规则端到端可命中。

## 本周做了什么

**1. 性能攻坚收口：四指标从全挂到三绿一降级**。W3 末的实测很难看：吞吐丢高优 15.6 万条、RSS 252MB、CPU 3.48%、P99 +34.6μs，四项全红。这周逐项打。先补观测性缺口：ringbuf 满了 reserve 失败以前不进任何计数器，60 万事件压进来有 32 万条对不上账。补齐 reserve_failed 和批溢出计数后，对账误差稳定 0.000%，后面的每轮优化才拿可信。然后是用户态大头：perf 归并显示 nlohmann JSON DOM 占消费线程 45-50%，改成手写 JSON 直写（逐字节等价）；祖先链每事件深拷贝改缓存指针加预序列化串。两刀下去消费线程从单核 98% 降到 31%，余量 3.2 倍。内核侧最后一块是 ring buffer 256KB 太小，10k/s 下只有 84ms 缓冲窗口，调度一抖就丢；扩到 2MB 后 5 分钟压测三轮 reserve_failed 全零。最后收口：RSS 252→123MB（队列槽位按需分配加 malloc_trim）、常态 CPU 4.60%→1.15%（空闲指数退避）、延迟 P99 归因完（调试计时代码已修，剩余是实时 wakeup 的调度固有尾，按 PRD 降级记录）。顺手修了一个老缺陷：同文件挂多条规则时 inode map 后写覆盖先写，read 规则静默失效，改成规则集合按 inode 合并。

**2. 规则引擎：DSL v1 + 解析器 + 匹配引擎**。W3 裁好的 40 项 CIS 清单需要一个载体，这周把规则引擎从纸面落到代码。路径是：先冻结事件 schema 字段表（docs/event-schema-v1.md，字段名是 DSL 的唯一来源），再设计 DSL（docs/rule-dsl-v1.md），然后解析器、引擎、接入消费线程。现在 rules/ 目录丢 YAML 就能跑，SIGHUP 热加载，3 条示例规则（反弹 shell、读 /etc/shadow、容器内 docker）端到端命中落库，告警带规则 ID、severity 和 ATT&CK 映射。

两个设计决策记一下。为什么对齐 Falco：规则语法的事实标准就是 Falco，安全用户第一眼看到 rule/condition/output/priority 就知道怎么写，学习成本是 PRD 的硬性要求（M3-9）；自造一套语法没有任何收益。为什么 v1 不做宏：宏是 Falco 规则体系里最贵的部分，嵌套展开、覆盖语义、循环引用检测，每样都是坑；v1 规则集就几十条，重复条件用内联 list 已经够写，等 W6 规则包扩充到出现真实重复再评估，现在做是提前消费复杂度。

**3. 告警风暴对账（M5-3 部分）**。造了条故意高频命中的规则打 1000 命中/分钟的风暴，验证冷却生效，并补了"已抑制 N 条"计数器（以前节流期告警跳过就跳过了，没有数）。详细数据和 M5-3 差距清单在 docs/alert-storm-w4.md。

**4. 引擎压测踩出一个历史遗留：用户态一直 -O0 构建**。100 条规则挂上后 10k/s 压测丢事件 28.5%，消费线程从 49% 冲到 93%。先怀疑求值慢，做了事件类型位图预过滤（规则编译期从条件提取"命中必须是哪种事件"，And 取交 Or 取并 Not 放弃约束），复测几乎没变化。插桩分段计时才看清：引擎求值加视图填充每事件 26.8µs，其中大头是 nlohmann json 迭代和标准库容器在 -O0 下的开销。翻 Makefile 才发现用户态 CXXFLAGS 从来没加过 -O，只有 BPF 侧有 -O2。以前的优化（R10 手写 JSON 直写）等于一直在给 -O0 打补丁。用户态全量切 -O2 后：引擎开销 26.8→4.0µs/事件，消费线程基线 48.7%→27.2%，单测 73/73 全过。一行 Makefile 改动，收益超过这周任何一轮手工优化。

## 最难的一个问题

消费线程单核 98% 的归因。现象是 10k/s 压测下 hi 队列持续溢出，但主线程 poll 只占 3-8% CPU，瓶颈显然在消费侧。perf 归并后栈顶是 JSON 序列化，占一半。麻烦的是不能只看占比砍：告警落库的 JSON 格式是既有契约，改序列化必须逐字节等价，否则下游查询全废。解法是手写渲染函数直写 buffer，拿 DOM 输出做逐字节 diff 验证等价，再切过去。第二刀祖先链深拷贝同理，改指针引用后要论证生命周期——缓存条目只在消费线程内被后续事件淘汰，事件处理期内引用恒有效。两刀都依赖一个前提：消费线程单线程无锁模型。这个前提现在值 3.2 倍余量，未来拆线程时是要连本带利还的债。
