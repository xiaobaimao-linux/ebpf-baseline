## 1. 背景与现状

### 1.1 现有能力

baseline-guard 当前是基于 eBPF LSM 的 Linux 内核级文件完整性监控（FIM）与基线核查工具，已具备：

- SQLite 基线快照全生命周期管理（snapshot / list / delete / check / clean）
- eBPF LSM 实时文件事件监控（write / chmod / chown / unlink），双模式运行
- 三类告警隔离与降噪冷却（yaml-rule / baseline / baseline-check）
- 钉钉机器人告警推送、HTML 审计报表
- 事件驱动低资源开销架构（默认无轮询）

### 1.2 现状问题

1. **功能单一**：仅覆盖文件完整性一个维度，无法回答"这台云主机/这个 AI 节点当前是否安全"这个完整问题。
2. **无上下文**：文件事件缺少进程、用户、网络、容器、GPU 等关联上下文，告警价值有限。
3. **无云与 AI 语义**：对容器、K8s、云元数据、GPU、模型文件、推理服务等现代负载无感知。
4. **单机孤岛**：无集中管控能力，多节点场景下策略、基线、告警无法统一。

### 1.3 市场机会与定位依据

- 云主机/容器运行时安全（CWPP/CNAPP 方向）普遍依赖内核级遥测，eBPF 已成为事实标准（Falco、Tetragon、Tracee 等）。
- AI 基础设施（训练集群、推理服务）成为新的攻击面：模型权重是高价值资产、GPU 是挖矿劫持目标、AI 供应链（模型文件、Python 包）投毒事件频发，而目前几乎没有以"AI 工作负载"为一等公民的轻量运行时防护产品。
- 现有通用 HIDS/EDR 对 AI 场景无专门建模；现有 FIM 工具（含本产品现状）只解决等保合规的单一条款。

## 2. 产品定位与愿景

### 2.1 一句话定位

**一个基于 eBPF 的轻量级主机安全 Agent 加集中管控平台，每台云服务器 / 每个 AI 集群节点安装一个 Agent，实时回答三个问题：这台机器上有什么资产、正在发生什么、有没有被攻击。**

### 2.2 目标客户（已确认）

**优先服务自建 GPU 集群的大模型公司 / 大型企业 AI 平台团队。** 该画像的直接影响：

- 集中管控、统一策略、审计留痕是刚需 → 管理中心（自研 Web 控制台）为核心交付物而非附属品
- 单客户节点规模大（数百至数千节点）→ Agent 资源占用、批量部署、灰度发布能力按大规模场景设计
- 客户有专业安全团队 → 规则可定制、数据可对接其 SOC/SIEM，而非仅做黑盒告警

### 2.3 产品形态

- **Agent（数据面）**：单二进制、低资源占用，安装于 Linux 云主机 / 容器节点 / GPU 服务器 / AI 训练推理节点，本地自治运行，断网可独立工作。
- **管理中心（控制面，自研 Web 控制台）**：多节点策略下发、基线统管、告警汇聚、资产总览、报表中心、权限与审计。Agent 不依赖管理中心也可完整工作，管理中心断连不影响节点检测。

### 2.4 商业模式（已确认，沿用现状）

- **开源核心**：Agent 核心检测能力开源（Apache 2.0），建立开发者信任与技术品牌。
- **企业版收费**：管理中心（Web 控制台）、高级规则包、主动响应能力、国产化适配支持、专属合规规则包（等保/CIS/行业）作为企业版能力。
- **规则包订阅**：威胁检测规则与情报库作为持续订阅服务更新，形成经常性收入。
- **定制与交付服务**：等保交付、二次开发、专属规则包定制（延续 baseline-guard 现有服务模式）。

### 2.5 设计原则（贯穿全文档）

1. **可观测优先，阻断谨慎**：以检测、审计、取证为核心；主动阻断能力默认关闭、逐能力灰度开启，绝不影响业务可用性。
2. **事件驱动，拒绝轮询**：延续现有架构优势，所有高频遥测基于 eBPF 事件，周期性任务只做兜底。
3. **单机自治**：Agent 任何功能在断网、无管理中心时必须可用，管理中心只做"聚合与增效"。
4. **合规即输出**：每一项检测能力都要能映射到等保 2.0 / CIS / MITRE ATT&CK / AI 安全框架的具体条款，可直接产出审计证据。
5. **AI 负载是一等公民**：模型、数据集、GPU、推理服务与进程、文件、网络并列作为核心监控对象，而非附加功能。

## 3. 目标用户与典型场景

### 3.1 目标用户

| 用户 | 诉求 | 优先级 |
| --- | --- | --- |
| **大模型公司 / 大型企业 AI 平台团队（首要）** | GPU 集群统一防护、模型资产保护、算力审计、集中管控 | 核心 |
| 政企运维 / 等保合规负责人 | 满足等保 2.0 三级"安全计算环境"审计要求，可产出取证材料 | 重要 |
| 云主机 / K8s 平台安全团队 | 节点级运行时威胁检测，容器逃逸与横向移动发现 | 重要 |
| 安全服务商 / 测评机构 | 批量部署、集中取数、出具合规与风险报告 | 一般 |
| 中小企业 / 开发者 | 低成本、开箱即用的服务器安全防护（通过开源版覆盖，建立漏斗） | 一般 |

### 3.2 典型使用场景

1. **AI 训练集群防护（核心场景）**：GPU 节点安装 Agent 后，管理中心统一看到：模型权重完整性状态、GPU 算力使用台账、非任务进程占用 GPU 告警、训练数据异常外传告警。
2. **推理服务防护**：发现推理服务进程异常派生子进程、模型加载路径被替换、推理 API 异常调用模式。
3. **云主机防护**：一台 ECS 安装 Agent 后，发现反弹 shell、挖矿进程、敏感文件篡改、异常提权。
4. **K8s 节点防护**：以 DaemonSet 部署，发现容器逃逸尝试、宿主机敏感目录挂载、容器内可疑执行。
5. **合规交付**：一键导出等保/CIS 核查报告，作为测评取证材料。

## 4. 产品范围

### 4.1 In Scope（本期做）

- Linux 主机与容器节点的运行时安全遥测与检测
- 云环境上下文感知（云厂商元数据、容器、K8s）
- AI 工作负载安全（模型资产、GPU、AI 进程、推理服务），含国产 GPU
- 基线核查（文件基线扩展至系统配置、软件资产、AI 资产）
- 告警、降噪、多渠道推送、审计报表
- 自研 Web 管理中心（多节点集中管控）
- 受控的主动响应能力（LSM 内核态阻断，默认关闭）

### 4.2 Out of Scope（本期明确不做）

- 网络层深度包检测（DPI）、WAF、NDR 全流量分析
- 完整 EDR 能力（远程取证 shell、全盘内存取证、威胁狩猎工作台）
- Prompt 内容级安全审计（prompt 注入语义检测、输出内容合规）——本期仅做 API 调用行为与流量元数据层面，内容检测留给网关类产品
- Windows / macOS 支持
- 漏洞修复、补丁管理等治理闭环（只做发现与报告）
- 模型安全评测（对抗样本、模型红队）——属于 AI 安全另一子领域，本期不覆盖
- 公安部销售许可证等销售资质认证（已确认暂不投入，商业销售启动前再行评估）

> 边界说明是内行文档的关键：明确"不做什么"与"做什么"同样重要，避免评审与交付期范围蔓延。

## 6. 功能需求详述

### M0. 现有 FIM 能力保留与增强

现有功能全部保留，作为 M2 基线核查子系统的组成部分。增强项：

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M0-1 | 文件基线支持进程上下文关联：告警中携带"谁（进程/用户/容器）修改了文件"，而非仅"文件被修改" | P0 |
| M0-2 | 进程白名单过滤，允许声明可信进程对受保护路径的合法写操作，降低误报 | P0 |
| M0-3 | 基线批量导入导出、基线版本化管理（多标签快照间 diff） | P1 |
| M0-4 | 系统内核参数/关键配置文件基线校验（sysctl、sshd_config、pam 等） | P1 |

### M1. 资产清点子系统（Asset Inventory）

**目标**：自动发现并持续维护节点资产清单，是一切检测与基线的前提。

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| M1-1 | 主机指纹 | OS 发行版/版本、内核版本、CPU/内存、云厂商与实例元数据（通过 169.254.169.254 只读获取，含实例 ID、Region、VPC） | P0 |
| M1-2 | 软件资产 | 已安装软件包（rpm/deb）、运行中进程清单、监听端口、开机自启项、定时任务 | P0 |
| M1-3 | 容器资产 | 本机容器/镜像清单（对接 containerd/docker/CRI-O 运行时接口）、容器与进程映射关系 | P0 |
| M1-4 | K8s 资产 | 节点角色、Pod 清单、命名空间（通过只读 API 或容器标签推断，不强依赖 API Server 凭据） | P1 |
| M1-5 | AI 资产 | GPU 型号/数量/驱动/CUDA 版本；AI 框架（PyTorch/TF/vLLM/TensorRT 等）及版本；模型文件与数据集目录发现（按扩展名与魔数识别：.pt/.pth/.safetensors/.bin/.onnx/.gguf 等）；Jupyter/推理服务端点 | P0 |
| M1-6 | 账号资产 | 本地账号、sudo 权限账号、SSH 授权公钥清单及变更 | P1 |
| M1-7 | 脆弱性初筛 | 基于软件清单与公开 CVE 库（本地离线库）的版本匹配初筛，标注"疑似受影响"，不做漏洞验证 | P2 |

**输出要求**：资产清单本地持久化，支持 JSON 导出与变更历史查询（"昨天和今天比多了什么进程/端口/容器"）。

### M2. 基线核查子系统（Baseline & Compliance）

**目标**：在现有文件基线之上，扩展为"系统 + 云 + AI"三类基线，支持主流合规框架。

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| M2-1 | 文件完整性基线 | 现有能力（M0 增强后），支持等保 2.0 条款映射 | P0 |
| M2-2 | 系统配置基线 | 内置 CIS Linux Benchmark 常用检查项（认证、SSH、日志、网络参数、权限），支持自定义 YAML 检查项；核查结果分级（pass/fail/warn） | P0 |
| M2-3 | 云配置基线 | 节点侧可核查项：云助手/agent 配置安全、metadata 服务访问控制、云存储挂载点权限、安全组相关本机端口暴露一致性 | P1 |
| M2-4 | 容器/K8s 基线 | CIS Docker/Kubernetes Benchmark 中节点侧可核查项（守护进程配置、kubelet 配置、文件权限）；容器运行时危险配置发现（privileged、hostPID/hostNetwork、敏感目录挂载、docker.sock 挂载） | P0 |
| M2-5 | AI 资产基线 | 模型权重文件/词表/配置文件的哈希基线（复用 FIM 引擎）；GPU 驱动与 CUDA 版本基线；AI 框架版本基线；推理服务端口与进程基线 | P0 |
| M2-6 | 基线策略包 | 内置等保 2.0 三级、CIS 两套规则包，规则包版本化、可更新、可自定义扩展；企业版提供行业专属规则包订阅 | P1 |
| M2-7 | 基线报告 | 按框架输出核查报告（HTML/JSON），含条款映射、不合规项整改建议，可直接作为测评辅助材料 | P0 |

### M3. 威胁检测子系统（Runtime Threat Detection）

**目标**：基于 eBPF 全量遥测，覆盖主机与容器的常见攻击行为（TTP），每条检测规则映射 MITRE ATT&CK 战术技术编号。

**遥测采集范围**（数据基础，不作为独立功能交付）：

- 进程：execve 全量事件（含完整命令行、父子关系、uid、容器归属）、进程退出
- 文件：沿用现有 LSM 文件事件，扩展敏感路径读事件（如 /etc/shadow、私钥、云凭证文件）
- 网络：connect/accept/bind 事件（五元组、进程归属），DNS 查询
- 权限：setuid/setgid、capabilities 变更、ptrace 调用、内核模块加载
- 挂载与命名空间：mount、unshare/setns（容器逃逸关键原语）

**检测能力需求**：

| 编号 | 检测类别 | 典型检测点（示例，非穷举） | 优先级 |
| --- | --- | --- | --- |
| M3-1 | 入侵执行类 | 反弹 shell、无文件攻击（memfd 执行）、/dev/shm 可执行、可疑解释器执行（curl\|bash 模式）、Crontab/自启项持久化 | P0 |
| M3-2 | 凭据与横向移动 | 读取 /etc/shadow、读取 SSH 私钥/云 AKSK 文件、暴力破解特征、可疑的内网扫描行为 | P0 |
| M3-3 | 提权与逃逸 | 危险 capabilities（SYS_ADMIN/SYS_PTRACE 等）使用、SUID 滥用、内核模块异常加载、容器逃逸原语组合（unshare+mount+cgroup 写等）、ptrace 注入 | P0 |
| M3-4 | 资源劫持 | 挖矿行为检测（进程特征+网络连接矿池+CPU/GPU 异常占用三因子关联）、容器资源异常 | P0 |
| M3-5 | 防御规避 | 日志清除/篡改、安全进程（含本 Agent）被 kill/停止、Rootkit 特征（隐藏进程/端口交叉比对：eBPF 视图 vs /proc 视图不一致） | P0 |
| M3-6 | Webshell 辅助检测 | Web 服务进程（nginx/java/php-fpm 等）派生 shell 或执行高危命令 | P1 |
| M3-7 | 容器专项 | 容器内执行 docker 命令、访问宿主机 docker.sock、容器逃逸后访问宿主机敏感路径、镜像外新增可执行文件运行 | P0 |
| M3-8 | 网络异常 | 连接已知恶意 IP/域名（本地离线情报库，可更新）、异常端口监听、DNS 隧道特征 | P1 |

**规则引擎需求**：

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| M3-9 | 规则 DSL：YAML 声明式规则（字段条件 + 逻辑组合），语法风格对齐 Falco 以降低用户学习成本；内置规则集开箱即用，支持用户自定义规则热加载 | P0 |
| M3-10 | 每条规则携带：ATT&CK 映射、严重等级、误报说明、处置建议 | P0 |
| M3-11 | 白名单体系：按进程路径/命令行/容器镜像/父进程链的多维白名单，支持规则级豁免 | P0 |
| M3-12 | 行为基线自学习（可选）：对进程树与网络连接建立 7 天学习期，偏离基线产生中低危告警 | P2 |

### M4. AI 工作负载防护子系统（AI Workload Security）

**本子系统是产品差异化的核心，目标是让本产品成为"最懂 AI 负载的主机安全产品"。**

#### M4.1 AI 资产与模型保护

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| M4-1 | 模型完整性保护 | 对模型权重/分片/tokenizer/推理配置建立哈希基线（复用 FIM 引擎），实时监控篡改、替换、未授权读取、批量外拷 | P0 |
| M4-2 | 模型加载监控 | 监控模型文件被哪些进程加载（open+mmap），非白名单进程加载模型即告警 | P0 |
| M4-3 | 模型供应链风险 | 发现使用 pickle 格式（.pt/.pth/.pkl）且来源不明的模型文件，提示反序列化代码执行风险；新出现的模型文件纳入变更审计 | P1 |
| M4-4 | 数据集访问审计 | 对声明的数据集目录记录访问审计日志（谁、何时、读了多少），发现批量读取+压缩+外传组合行为 | P1 |

#### M4.2 GPU 与算力防护（含国产 GPU，已确认支持）

**设计要求（P0）**：GPU 遥测必须抽象为统一接口（采集层与厂商实现解耦），禁止把 NVML 调用写进业务逻辑，国产 GPU 以插件形式接入。

| M4-6 | 国产 GPU 支持 | 华为昇腾（npu-smi / Ascend 驱动接口）、海光 DCU（ROCm 系接口）、摩尔线程（MUSA 工具链接口）；至少完成昇腾与海光两家适配，输出《国产 GPU 适配清单》。**验证策略（不要求自购硬件）**：① 开发期基于厂商文档与社区真实输出样例构建 golden file 契约测试（mock 数据源，覆盖解析与降级逻辑）；② 联调期租用云实例验证（昇腾经华为云 ModelArts/算力租赁平台按小时租用，海光经生态适配中心/经销商申请远程测试机）；③ 验收期通过厂商生态计划（昇腾万里伙伴计划、海光生态适配中心）获取测试环境并完成兼容性互认证。**验收标准**：在真实昇腾/海光环境上，利用率/显存/进程映射采集值与厂商原生工具输出误差 ≤ 5%，模拟非授权进程占用 GPU 时算力劫持告警 ≤ 10s 触发 | P1 |
| M4-7 | 算力劫持检测 | 非任务白名单进程占用 GPU 即告警（GPU 挖矿/盗算）；GPU 长时间高占用但无已知训练框架进程特征时告警 | P0 |

## 7. 非功能需求

### 7.1 性能

| 指标 | 要求 |
| --- | --- |
| CPU 占用 | 常态 ≤ 3% 单核（GPU 节点 ≤ 5%），事件风暴时限额降级不超 10% |
| 内存占用 | 常驻 ≤ 150MB（含 SQLite 缓存），硬上限 300MB |
| 磁盘 | 数据目录默认上限 2GB 可配；安装包 ≤ 50MB |
| 事件延迟 | 内核事件到告警落库 P99 ≤ 2s |
| 事件吞吐 | 单节点 ≥ 10,000 事件/秒不丢核心高优先级事件（可丢弃低优先级并计数） |
| 对业务影响 | eBPF 探针引入的系统调用额外延迟 P99 ≤ 5μs；禁止引起业务可感知抖动；AI 训练任务吞吐无可感知下降 |
| 管理中心 | 支撑 2,000 节点接入；告警查询 P95 ≤ 3s（千万级告警量） |

### 7.2 兼容性

| 维度 | 要求 |
| --- | --- |
| 内核 | Linux ≥ 4.18（LSM BPF 需 ≥ 5.7 完整能力，低版本内核功能降级并明确提示缺失能力清单） |
| 发行版 | CentOS/RHEL 7+、Ubuntu 18.04+、Debian 10+、openEuler、Anolis、统信 UOS、麒麟（国产化适配是政企与大客户市场硬要求） |
| 容器运行时 | containerd、docker、CRI-O |
| K8s | 1.20+，DaemonSet 部署 |
| 云环境 | 阿里云、腾讯云、华为云、AWS、私有云（OpenStack）元数据识别 |
| GPU | NVIDIA（CUDA 10+，NVML）；**国产 GPU（昇腾、海光 DCU 为明确需求；摩尔线程跟进）**，见 M4-6 |
| 架构 | x86_64、ARM64（ARM 服务器与国产化场景，含昇腾 ARM 主机） |

### 7.3 安全

- Agent 二进制与规则包签名校验
- 与管理中心通信 mTLS；本地 API 仅监听 Unix Socket
- 配置文件含敏感项（webhook secret 等）权限 600 检查
- 自身不产生新攻击面：不监听 TCP 端口（默认）、不引入多余依赖

### 7.4 可靠性

- 进程崩溃自动重启（systemd Restart=always）+ 崩溃现场保留（core/最后日志）
- eBPF 程序加载失败时按能力降级运行（如 LSM 不可用时退化为 tracepoint/kprobe），不直接退出
- 数据损坏自恢复：SQLite 损坏检测与备份回滚
- 管理中心故障不影响任何节点检测与本地告警推送

### 7.5 可维护性

- 结构化日志（JSON），日志级别动态可调，支持日志轮转
- 关键路径埋点：事件吞吐、丢弃率、规则命中率、SQLite 延迟
- 诊断命令：`doctor` 一键输出环境兼容性自检报告（内核特性、eBPF 能力、GPU 接口、权限、磁盘）

## 10. 风险与依赖

| 3 | 主动响应 | 做 LSM 内核态阻断（默认关闭 + dry-run + 灰度） |
| 4 | 国产 GPU | 明确支持，昇腾/海光优先（M4-6） |
| 5 | 目标客户 | 自建 GPU 集群的大模型公司/大型企业 |
| 6 | 品牌 | 启用新品牌（候选见 11.2） |
| 7 | 合规认证 | 暂不投入，商业销售启动前再评估 |

## 12. 附录

### 12.1 术语表

| 术语 | 说明 |
| --- | --- |
| FIM | File Integrity Monitoring，文件完整性监控 |
| eBPF LSM | 基于 Linux Security Module 钩子的 eBPF 程序，可在内核态做访问决策 |
| CWPP | Cloud Workload Protection Platform，云工作负载防护平台 |
| TTP | Tactics, Techniques and Procedures，攻击战术技术过程 |
| ATT&CK / ATLAS | MITRE 的攻击技术知识库（通用 / AI 专用） |
| 行为基线 | 对正常行为的统计画像，偏离即异常 |
| CO-RE | Compile Once Run Everywhere，eBPF 跨内核版本移植技术 |
| Air-gap | 离线隔离环境，指无外网的部署场景 |
| NVML | NVIDIA Management Library，NVIDIA GPU 用户态管理接口 |
| Dry-run | 干跑模式：只记录"如果阻断会发生什么"，不实际执行阻断 |
| Agent（术语冲突提示） | 本文档中 Agent 一律指**主机安全代理**（部署在节点上的探针程序）；行业语境中 "AI Agent" 指大模型驱动的智能体应用，两者同名不同物。对外市场材料中建议主机侧组件使用"探针/Sensor"或产品名前缀，避免客户误认为本产品提供 prompt 层防护 |

### 12.2 需求优先级定义

- **P0**：核心能力，缺失则该版本不成立
- **P1**：重要能力，影响竞争力与交付完整性
- **P2**：增强能力，可按资源情况延后
