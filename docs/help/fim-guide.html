文件完整性监控（FIM）使用手册

谛听的 FIM 能力由两部分组成：SQLite 基线快照（静态可信基准）与 eBPF 实时监控（运行时篡改检测）。本手册覆盖全部子命令参数、双模式差异、告警规则与钉钉配置。

1. 基线快照管理（baseline 子命令组）

所有子命令默认读取内置默认 SQLite 库，支持 --db 自定义路径。数据表：baseline_entries（基线记录）、alerts（告警持久化）。

1.1 snapshot 采集可信基线

递归扫描文件/目录，写入哈希、权限、属主；重复执行自动更新条目。

# 采集 /etc 基线，自定义标签，排除缓存目录
sudo ./baseline-guard baseline snapshot /etc --label release-202608 --exclude /etc/cache
# 仅扫描一级目录，不递归
sudo ./baseline-guard baseline snapshot /tmp/fimtest --no-recurse
# 指定独立数据库
sudo ./baseline-guard baseline snapshot /tmp/fimtest --db /var/lib/baseline-guard/baseline.db
参数说明
PATH待采集文件/目录，支持多路径
--db PATH指定 SQLite 基线库
--label NAME快照标签，默认 default
--exclude PATH排除路径，可多次使用
--no-recurse目录仅扫描直接子项

1.2 list 基线清单查询

sudo ./baseline-guard baseline list --path-filter "/tmp/fimtest/%"
sudo ./baseline-guard baseline list --limit 50 --offset 50
sudo ./baseline-guard baseline list --json > baseline_backup.json
参数说明
--path-filter PATTERNSQL 模糊匹配，% 为通配符
--limit N / --offset N分页控制
--json标准 JSON 输出

1.3 delete 删除基线记录

仅删除库内条目，不会删除磁盘真实文件。

sudo ./baseline-guard baseline delete /tmp/fimtest/newfile.txt
sudo ./baseline-guard baseline delete /tmp/fimtest --recurse

1.4 check 离线基线全量核查

读取基线库与磁盘真实文件比对，识别 4 类风险；告警入库，支持钉钉推送与 HTML 报表。

sudo ./baseline-guard baseline check
sudo ./baseline-guard baseline check --send-webhook --config config.yaml
sudo ./baseline-guard baseline check --report_html baseline_report.html
sudo ./baseline-guard baseline check --path-filter "/tmp/fimtest%"
参数说明
--db PATH指定基线数据库
--path-filter PATTERN限定校验路径范围
--send-webhook开启钉钉推送，依赖 --config
-c/--config加载含钉钉 webhook 的 YAML 配置
--report_html FILE输出 HTML 合规报表
--jsonJSON 结构化差异输出

比对风险类型：

event_type等级触发场景
missinghigh基线存在，磁盘文件已删除
hash_changedhighSHA256 不一致，内容篡改
perm_changedmediumUID/GID/权限变更
access_failedmedium无权限读取，无法校验哈希
关键规则：仅校验库内存在的基线文件；不跟随软链接；文件已偏离基线时，重复执行 chmod 至违规值仍会告警。

1.5 clean 清理僵尸基线

sudo ./baseline-guard baseline clean --dry-run   # 预演，仅打印
sudo ./baseline-guard baseline clean             # 执行清理

2. monitor 实时监控（双模式）

基于 eBPF LSM 捕获 write/chmod/chown/unlink 等文件操作。

2.1 纯 YAML 监控（无 --db）

sudo ./baseline-guard monitor -c config.yaml

仅按 file_rules 规则匹配路径事件，产出 yaml-rule 告警；不加载基线、不自检、无比对。

2.2 基线监控模式（携带 --db）

# 默认：启动先全量自检，再进入实时监控
sudo ./baseline-guard monitor --db baseline.db -c config.yaml
# 跳过开机自检
sudo ./baseline-guard monitor --db baseline.db -c config.yaml --skip-boot-baseline-check
# 可选兜底定时扫描（最小 60s，默认关闭）
sudo ./baseline-guard monitor --db baseline.db -c config.yaml --baseline-scan-interval 300
参数类型默认说明
--skip-boot-baseline-check布尔关闭跳过 monitor 启动自检
--baseline-scan-interval SEC整数未启用兜底周期全库扫描；<60 直接报错；告警独立冷却

2.3 告警来源区分（统一存 alerts 表）

来源产出冷却策略
baseline-check开机自检 / 定时扫描 / 手动 check独立 5 分钟冷却
baseline实时捕获文件操作比对基线发现篡改1 分钟降噪
yaml-rule纯 YAML 规则匹配沿用告警节流策略
架构优化点：移除默认 10s 高频轮询；仅开机一次自检兜底存量篡改，无后台持续扫描。

3. 告警查询与报表

sudo ./baseline-guard alerts                     # 最新 20 条告警
sudo ./baseline-guard alerts --rule baseline     # 仅实时篡改告警
sudo ./baseline-guard report --start 2026-08-01 --end 2026-08-15 -o full_audit.html

4. 钉钉告警配置

# config.yaml
dingtalk:
  webhook_url: "https://oapi.dingtalk.com/robot/send?access_token=xxx"
  secret: "SECxxxxxxx"        # 生产环境启用签名校验

file_rules:                   # 纯 YAML 监控模式的文件规则
  - path: "/tmp/fimtest/*"
    events: ["write", "delete", "chmod", "chown"]
约束：使用 --send-webhook 必须通过 -c/--config 加载配置，缺失则仅本地存告警、不推送并打印警告。

5. 核心逻辑规则（测试验证定稿）

  1. 基线比对仅对比磁盘当前真实元数据与库内基线，不判断单次操作前后是否变化；文件已偏离基线时，重复执行同一 chmod/chown 仍产生 perm_changed 告警。
  2. monitor 基线模式启动执行一次全基线自检捕获停机期间篡改；自检后无后台自动扫描，仅靠 eBPF 事件驱动校验。
  3. 定时兜底扫描默认关闭；启用强制最低 60 秒间隔，扫描告警独立冷却。
  4. baseline delete 仅删库内记录，删除后 check/monitor 均不再校验该路径。
  5. monitor 不带 --db 时完全隔离基线逻辑，仅执行 YAML 路径事件监控。

6. 标准链路速查

make
mkdir -p /tmp/fimtest && echo "test" > /tmp/fimtest/test.txt
sudo ./baseline-guard baseline snapshot /tmp/fimtest
sudo ./baseline-guard baseline check
sudo ./baseline-guard monitor --db baseline.db -c ./config.yaml
# 另开终端模拟篡改：
echo "modify" > /tmp/fimtest/test.txt && chmod 777 /tmp/fimtest/test.txt
sudo ./baseline-guard alerts
sudo ./baseline-guard report -o fim_audit_report.html
